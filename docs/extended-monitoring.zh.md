# 扩展监控方案：隐私、节点健康、设备带宽

2026-10-04。Fork：`ccawmiku/neko-master`。上游基线：`6f72cfd0db69e2952713f24a648812407fef1e78`。开发分支：`feat/extended-monitoring`。

当前状态：完成源码研究、fork 和真实路由器 nlbwmon 只读接口核实。本文是实施设计，不代表新增功能已经实现或性能已经改善。OpenClash 现代化界面停止新增开发，已部署的 DNS 防护、采集和原代理配置继续运行。

## 产品范围

扩展 Neko Master 自身的监控范围，统一使用现有 React、shadcn/ui、Tailwind、Recharts、时间筛选、设备筛选与明暗主题。不能把旧 Vue 页面作为 iframe 当作完成 UI 迁移。

| 入口 | 内容 |
| --- | --- |
| 总览 | 保留原代理流量概览，新增隐私证据摘要、节点健康与路由器带宽摘要；明确数据来源和更新时间 |
| 隐私与安全 | 加密/明文/未知、协议、DNS、WAN SNI、国外直连、覆盖缺口、历史风险与证据详情 |
| 节点 | 保留现有代理统计，增加独立健康视图：逐节点历史延迟、探测成功率、抖动、故障与恢复时间线 |
| 设备 | 保留现有设备代理流量视图，增加 nlbwmon 路由器流量账本：上传/下载、排行、IPv4/IPv6、计费周期与增量趋势 |
| 原有规则/域名/国家等 | 原有入口与功能保持可用，不将原统计替换为另一个统计口径 |
| 设置 | 独立的采集、探测、历史保留与数据源设置；DNS 实际保护配置由路由器执行并回读确认 |

节点健康与设备带宽增强已有入口，避免创建名字不同但内容重叠的页面。原后端健康监控继续表示 Collector 到网关的健康，不能拿它代替逐节点探测。

## 部署与数据来源

路由器只运行轻量采集、有界上报、独立 DNS 与防火墙。Neko Web、Collector、关联分析和历史数据库先在受限本机环境开发验证，生产部署位置另行落实。完整 Node.js/Next.js 服务不直接增加到当前路由器。

三种来源独立上报、独立存储与统计，不相加：

- **Mihomo**：节点、命中规则、域名与经过核心的流量；沿用现有 Neko 统计。
- **隐私观察器**：WAN/LAN 协议证据、明文 DNS、可见 SNI、NAT 关联与采集覆盖状态。
- **nlbwmon / 接口计数器**：设备流量账本与接口实时带宽；代理关闭时继续采集。

共享 backendId、时间范围与设备关联维度，但不保证三个来源的字节数相等。抓包、核心应用流量、conntrack 账本和接口字节各有开销、覆盖与观察位置差异。代理流量不能再添加到设备总流量，也不能简单用“总量减代理量”推导设备直连量。

## 隐私证据与保护

隐私页面必须保留未知类别与覆盖缺口。443 不等于确认加密，核心 sniffHost 不等于 WAN 可见 SNI，ECH 提议不等于隐藏成功，LAN 明文 DNS 不等于外网 DNS 泄露。

国内外判断复用 Mihomo 实际规则/内容及目标 GeoIP，冲突与缺失为未知，不新增网站分类库，不用节点所在地代替目标分类。现有 Neko 的 GeoIP 默认在线查询；本地 MMDB 查询失败也会在线回退。隐私部署须增加显式外部查询禁用策略，不能仅切到 local 模式。

独立安全 DNS 保留阿里 DoH 主用、腾讯 DNSPod DoH 备用及全部上游不可用时不回退明文的行为。代理、Neko 面板或 Collector 停机不会撤销保护；代理关闭时核心分类证据可能缺失，但基础抓包和 DNS 防护继续运行。

先使用现有 router-privacy 快照接入原生 React 页面，再把昂贵的关联和汇总移到 Collector。已有快照是当前缓存累计计数，不是每次新增流量；不能直接累计快照或补造旧历史。

## 节点监控

通过 Mihomo 的标准能力获取具体节点及探测结果，不把策略组、DIRECT、REJECT 混作普通节点。记录节点类型、提供者、探测目标、时间、结果、延迟、超时与错误原因；身份变化保留历史边界。

延迟明确为所选目标的 HTTP/HTTPS 探测延迟，不称作 ICMP ping。探测成功率只表示采样结果；缺失时段是未知，不能当作连续在线或故障。

图表包含延迟趋势、P50/P95、抖动、状态时间条及故障/恢复事件。目标服务故障与节点故障不能只靠一次超时区分。默认低并发、有间隔和随机错峰，优先复用可用的核心历史结果；提供受限手动复测，避免全节点频繁探测造成负载和额外流量。

现有独立节点历史服务可以作为首阶段适配来源。之后再整合到 Neko 的采集调度和存储，避免新旧两个调度器同时探测同一批节点。

## 带宽与 nlbwmon

2026-10-04 真实路由器只读核实：`nlbw -c json` 可用，返回 `columns` 与 `data`，字段包含 `family, proto, port, mac, ip, conns, rx_bytes, rx_pkts, tx_bytes, tx_pkts, layer7`。不将实际 MAC、IP 和用户访问数据提交公开仓库。

当前刷新间隔 30 秒、持久化间隔 24 小时、账本每月 1 日换期、保留 10 个周期。新增上报不改变原账本，不触发额外 commit 或另起一个 nlbwmon 守护进程。

设备上传/下载与历史用 nlbwmon 的只读 JSON 和历史周期接口；WAN 实时速度使用选定接口字节计数器的时间差。设备曲线精度受源刷新间隔约束，不能展示成每秒精确采集。nlbwmon 的协议分类主要依赖端口定义，不作为隐私页面的实际协议或加密证据。

先导入已有周期总量，再从接入时刻开始记录增量。过去的月账本不能还原逐日或每秒历史。换期、数据库重建、计数器回退、重连和重复上报分别处理，不用 Agent 重启时间代替 nlbwmon 的账本周期。

设备关联优先使用可靠的 MAC 与来源作用域，结合 IP 租约/名称映射。缺失 MAC、IPv6 地址变化、访客网络与随机 MAC 必须明确展示关联能力；不能将所有未知 MAC 合并成一个“设备”。

**计数器冲突**：nlbwmon 使用 conntrack zero-on-read 机制。隐私模块读取 conntrack 主要用于 NAT/连接关联，不把这些计数器当作始终单调累加的长期流量来源。设备总量由 nlbwmon 负责，隐私比例由 WAN 捕获的独立计数负责；覆盖不足显示缺口。流量卸载对账本和抓包的影响分别核实。

## 扩展与升级约束

目前未确认公开的第三方 UI 插件 SDK。采用独立功能目录、Fastify 模块、共享版本化契约和小范围注册补丁，保留 upstream remote；不承诺上游升级完全零维护。

隐私、节点、设备账本使用独立消息契约，复用原 Agent 认证、backend 绑定、请求去重及限流设计。若修改已有 Agent payload，遵循上游 AgentProtocolVersion 与服务端最低版本约束。离线缓冲有容量上限，溢出记录缺口，不无限写路由器闪存。

数据库变更按上游开发规范同步处理 schema、迁移、保留、backend 删除、共享类型及 ClickHouse 对应行为。新数据的唯一键包含来源作用域、账本/观察器周期和批次身份，重试不能重复增加流量。

新增 UI 文案同时提供中英文，使用原有组件与主题，不硬编码另一套布局和配色。加载、无数据、故障及部分覆盖独立展示。探测和监控默认低频、有资源预算，历史聚合和界面查询在中心执行。

## 实施顺序与验收

1. 建立 fork、确认数据来源与契约，保持原生产服务稳定。
2. 先迁移核心隐私页面并对接真实证据，再增加历史、去重与严格时间区间统计。
3. 增强节点健康页面，迁移现有历史与探测调度，消除重复探测。
4. 增强设备页面，接入现有 nlbwmon 账本、接口带宽与周期历史。
5. 将路由器关联汇总逐步移出，做相近业务负载的 CPU/RSS/采集缺口对照。
6. 验证代理关闭、Collector 离线、计数器换期、身份变化、重复/迟到批次与恢复；再切换生产入口。

不以静态演示数据代替真实监控；不能恢复的旧数据明确标记，不制造过去的时间曲线。验收包括真实数据对账、无重复计数、明暗主题、中英文、手机布局、页面离开停止刷新、资源受限和安全 DNS 独立运行。
