# 路由器 Docker 部署与实测

2026-10-04 在 Dell Wyse 3040（Atom x5-Z8350，4 核、约 1.85 GiB 内存，iStoreOS 24.10.6 x86_64）部署。监控中心运行于 Docker，DNS 保护、抓包、节点探测、设备计量继续由原生 `neko-smart` 服务执行。容器停止时 DNS 仍能解析，代理保持运行。

## 部署配置

安装与设备架构和 OpenWrt 版本匹配的 `neko-smart-router` 包。本次更新使用 0.1.0-r9。配置原生服务的中心地址及连接令牌后，运行：

```sh
docker compose -f docker-compose.router.yml up -d
```

网页端口 18082，API 3001，WebSocket 3002。中心保持用户选择的免登录模式；原生上报仍使用独立令牌。不要导出含连接密钥的数据库或路由器配置到公开仓库。

免登录入口须限制在可信 LAN。实机检查发现原 WAN input 为 ACCEPT，现已添加 `neko_smart_management` 规则限制校园网侧的管理、内核控制与本地 DNS 服务访问。部署时应检查宿主防火墙和 Docker 网络模式；不能只靠私有 IP 判断可访问范围。分类与本次修复说明见 [隐私分类与设备范围](privacy-metrics.zh.md)。

容器限制 512 MiB 内存、1.5 核 CPU、128 个进程，删除 Linux capabilities，启用 `no-new-privileges`。运行数据库位于 `/app/runtime` 的 256 MiB tmpfs；该上限按需使用，并计入容器内存限制。`/tmp` 上限 32 MiB，容器日志使用 local driver，最多 2 个 1 MiB 文件。宿主不支持 swap 限制，当前没有配置 swap。

镜像在 CI 构建，路由器只拉取运行镜像。本次实机使用 CI 生产构建，并通过 digest 固定部署。默认 Compose 跟随正式 `latest`，维护时也可将 `image` 改为验证过的 digest。

## 原有数据与控制

使用 SQLite 在线备份迁移 35 张表。保留网关、连接令牌、监控设置、流量历史、7 个节点历史和原始带宽统计周期。停掉电脑端采集后才启动路由器中心，避免双重采集。原 OpenClash UCI 和两个 YAML 文件的 SHA256 与迁移前相同，其他 3 个 Docker 服务状态保持不变。

概览中的启停、运行模式、代理模式、区域绕过、嗅探、DNS 代理与流媒体开关通过原生白名单助手执行。助手调用原 OpenClash 操作处理器，保留其覆写行为。命令有有效期和执行回执，重启不重放旧命令。Mihomo 首次连接建立流量基线，避免再次计入已有连接的累计字节。

## 内存与 eMMC 写入

数据库读写在内存完成，每小时在线备份到 `/overlay/neko-smart-center/stats.db`；正常停止时额外备份。写临时文件后校验、同步文件与目录，再轮换主备份和上一份备份。重启恢复及全部表记录保留已在实机验证。

意外断电可能丢失最近一个备份周期内的中心统计。节点历史另按小时保存，设备计量保留迁移前的每日写入设置；抓包与监控快照位于 RAM。此策略减少周期性闪存写入，无法消除备份和镜像更新的写入。

当前数据库约 9.4 MiB，按每小时完整备份估算约 226 MiB/日逻辑写入，实际随数据量变化；文件系统和 eMMC 内部写放大另外计算。设备 `life_time=0x01/0x01`、`pre_eol_info=0x01`，属于粗粒度的早期寿命区间和正常备用块状态，不能据此推算剩余年数。大规模或长期历史应使用外接 SSD，并监测 tmpfs 及数据库大小。

## 实机验收

生产构建和类型检查通过，Collector 13 个文件、88 项测试通过。新增组件定向 lint 通过；全量前端 lint 有上游既有错误。真实路由器页面覆盖核心控制 6 个子页、4 个监控页、明暗主题、1440px 桌面和 390px 手机，中英文入口可用，未发现 JavaScript 错误或整页横向溢出。测试等待数据和图表实际出现后截图。1200px 下带宽统计为一行四张卡片，每张高 136.5px。

5 分 11 秒窗口内，同时执行页面切换、图表渲染和 20 次完整监控 API 请求：中心平均 CPU 为单核的 42.2%，容器最高内存约 150.3 MiB，容器块设备写入增量为 0；路由器仍有约 627 MiB 可用内存。完整 API 响应约 2.95 MB，P50 约 1.07 秒，P95 约 1.32 秒。采样不包含镜像拉取、启动和定期备份，也不代表持续满速流量负载。

随后关闭浏览器进行 124 秒后台采集检查：平均 CPU 为单核的 17.7%，最高内存约 139.9 MiB，块设备写入增量为 0。该测量只统计中心容器；原生抓包、DNS、节点和带宽服务不计入容器数值。上述数据采集于最后一次图表事件标记样式调整前，后端与运行配置相同。

当前家庭网络负载下可运行；上述结果属于短期实机检查，持续大流量、更多设备和长期数据库增长需要另外验证。国内外分类来自 Mihomo 规则与目标地区信息，无法归类的连接保留未知；抓包丢包和覆盖范围在隐私页显示。零告警不自动代表所有流量安全。
